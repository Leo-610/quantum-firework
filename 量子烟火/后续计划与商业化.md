## 二、产品愿景（12–24 个月）

**一句话**：北交大首个「空间化情感 × 烟火日常」双模态校园智能体；从 Demo 进化为**校内可运营的数字情感基础设施**。

**不做**：心理咨询替代品、食堂官方评价系统、通用 Chatbot。  
**要做**：低门槛情绪着陆 + 有空间记忆的校园文化表达 + 可对接学校官方服务的入口。

**North Star Metric**：**每周完成一次情绪着陆（倾诉 + 植物落地）的独立用户数** — 同时体现里世界价值与空间化差异。

## 三、火山杯一等奖 · 冲刺策略

### 3.1 评委在找什么

| 维度 | 我们要证明的 |
|------|----------------|
| 30 秒看懂 | 量子 × 烟火、里表世界、北交大强绑定 |
| 3 分钟记住 | 空间 + AI + 多智能体，不是换皮 ChatGPT |
| 5 分钟讲清技术 | Router / Inner / Outer / Workflow 分工 + Coze 价值 |

### 3.2 推荐执行顺序

```
Week 1  演示模式 + Router 可视化 + 分享卡片生成器
Week 2  情绪时间轴/图鉴 + 世界切换仪式 + 危机引导
答辩前  5 分钟脚本排练 + 预置 demo 数据 + 心理中心/学工一句话反馈
```

### 3.3 五分钟答辩故事线

| 时段 | 内容 |
|------|------|
| 0:00–0:30 | 痛点：情绪没地方落、吐槽没温度、空间与情感断连 |
| 0:30–1:30 | 双世界：切换仪式 → 地图变色 → 建筑配色联动 |
| 1:30–3:00 | 里世界：倾诉 → 流式回应 → 植物落地 → 时空回响 |
| 3:00–4:00 | 表世界：吐槽 → 文豪改写 → 雷达 → **分享卡片扫码** |
| 4:00–4:30 | 技术：Router 可视化 + Coze 工作流 + 心理中心地图 + 合规 |
| 4:30–5:00 | 愿景：校内情感基础设施，非心理咨询替代品 |

### 3.4 如果只选 3 个必做项

1. **ShareCardGenerator** — 传播闭环 + 答辩现场可扫码  
2. **DemoMode** — 网络/Coze 波动时 demo 不翻车  
3. **RouterTraceHud** — Coze 多智能体架构可视化

### 4.6 阶段 2 · 账号与云同步（4–8 个月）

#### 登录方案（北交大优先）

| 方案 | 优点 | 缺点 | 建议 |
|------|------|------|------|
| **学校统一认证（CAS/OAuth）** | 官方背书、天然限校内 | 需信息化中心对接 | ⭐ 首选 |
| 企业微信 / 微信扫码 | 传播快 | 需绑定学工号 | 备选 |
| `@bjtu.edu.cn` 邮箱验证码 | 实现快 | 非实时学籍校验 | 过渡 |
| 自建用户名密码 | 完全自控 | 安全与运维成本高 | 不推荐 |

#### 数据架构（建议）

```
浏览器 → Auth（JWT Session）→ Vercel API → Postgres（Neon / Vercel Postgres）
                                              ├── users
                                              ├── emotion_plants
                                              ├── user_settings
                                              └── audit_logs（敏感操作）
Coze user_id ← 稳定账号 ID（非随机 UUID）
```

**存储策略（里世界敏感）**：

- 默认：**plants 元数据上云**（坐标、类型、时间、摘要），**对话原文不上云或 7 天 TTL**
- 用户可「一键删除全部云端记录」
- 管理端仅看聚合统计，不看个体明文（除非法务/危机干预流程）

- [ ] 登录 / 登出 / 会话续期

- [ ] 跨设备同步 plants 与个人设置

|------|------|--------|

## 八、合规、风险与伦理

1. **里世界数据**：上云前须过学校法务与心理中心共识。  
2. **AI 幻觉**：持续强调「非心理咨询」；危机词库 → 心理中心（S-07）。  
3. **表世界 UGC**：人身攻击、造谣 → 审核 + 举报。  
4. **统一认证**：遵循学校信息化管理规定。  
5. **等保与备案**：校内正式部署可能要求 ICP + 等保二级。
